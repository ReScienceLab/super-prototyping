# The app opens on its home page

2026-09-21. The desktop app used to open the last project straight onto its canvas, and asked
which project only on the first launch. Now the first launch is still the startup page, which
picks an agent and a project, and every later one opens `home.html`: every project as a card,
and the examples beside them. The canvas's top bar has a Home button back to it.

## Projects first, canvases one click in

A project is a folder under `Documents/Super Prototyping`, and its `mockups/canvases` holds
one canvas or several. Most hold one, worked on for the whole project, so that card shows the
canvas's own screens and opens it. A project of several, iterations or styles side by side,
shows each canvas's cover and opens on the one edited last. An example is a project of one
canvas that the app ships.

## A tab is a project

This replaces a tab per canvas (`2026-09-21-canvas-tabs.md`). The bar across the top holds one
tab per project open, examples included, and each remembers the canvas it was left on. The bar
runs the full width of the window, and everything of one project is under it. It is drawn after
Figma's desktop strip, on the canvas and the home page alike: a raised row of cells of one width
split by hairlines, the one in front on the page's own ground, a long name fading at the cell's end.

The bar's "+" is a menu: New project first, then every project and example. New project is the
window's dialog, so it opens in place over the home page and a canvas alike. Only the app can
make a project, so a browser's "+" has no New project.

## A project's canvases are tabs under its tab

Under the bar, across the top of the project, is a row of its canvases (`CanvasStrip.tsx`):
tabs of the second level, drawn as Geist's Tabs are, a name underlined when it is in front,
so they do not read as more of the bar's cells. It replaced a rail down the left after Figma's,
whose Canvases panel listed them on their side and did not look like a level under the bar's
tab. The panel's list of the boards on the canvas in front went with it; the canvas shows them.

The row's "+" is a new canvas, which only the agent can make: a folder with no boards in it is
not a canvas. So it puts the agent's panel out with "Make a new canvas for " in its box, over
nothing the user had written. At the row's far end is Export to Figma, which left the top bar
for it: it opens the canvas's sheet, the page that walks through the import, and in the desktop
app opens it in the browser, because the importer is a browser extension (`desktop/main.ts`).
The bar's Brand kit button went too; a kit is still at its address, `brand.html`, and linked
from the sheet.

## The agent is the app's

The agent's panel is down the left of the window on the home page and every project alike, the
same conversation whichever tab is in front. A run is still in the project whose page sent it, and
the history names that project on each row. The server keeps one list of runs for all of them
and one run at a time. The button at the start of the bar shows and hides the panel. It is a
toggle button, `aria-pressed`, drawn as a chip rather than as a tab, since it is not a place,
and it wears the mark of the agent the next message goes to, Claude Code or Codex. A right-click
on it is the menu of agents, which the mark in the panel's header used to open; that mark went,
as the same mark twice one above the other. The menu is beside the panel rather than in it, so
it opens while the panel is away. Whether the panel is out is `sp-chat-open` in `localStorage`,
out by default, and the agent is `sp-chat-agent`.

Open tabs are `sp-project-tabs` in `localStorage`, one list for the whole app: a project by its
address, an example by its slug, each with its view. A chip on the project in front switches
the view in place; a chip on another project loads that project's canvas beside the panel,
which stays as it was (`2026-09-22-app-shell.md`).

The page is drawn on the canvas's own Geist scale, `tokens.css`, not a palette of its own: the
same black ground, hairlines, chips and radii, so going home from a canvas does not look like
leaving the app. It began in greys sampled off Figma's home, which made it the one page in the app
on a different ground.

## Start here is a tab like any other

Start here was the one chip on the canvas's bar with no close, as the page every other tab fell
back to. With a home page to fall back to, it is an ordinary tab: closed like any other and opened
again from the "+". Closing the last tab leaves the canvas for `home.html`, the way closing
Figma's last file does, rather than reopening Start here nobody asked for.

## One server for every project

With a tab per project, restarting the server on each switch would make every click on the bar a
server start. So the desktop app runs one server for its whole life, and each project is a path
on it: `/p/<name>/` is that project's canvas, home page, boards and `/__sp`, made the first time
the path is asked for and kept. The built app is loaded with a relative base (`base: "./"` in
`vite.config.ts`), so the same files work under any project's path, and every fetch the client
makes is relative to it.

`<name>` is a folder in `PROTOTYPING_PROJECTS_DIR`. A folder opened from anywhere else is named
when the app opens it: the app sends its path over the server's parent port and is answered the
address, and the server numbers the name past any project already called that. Only the app can
ask, since only the process that started the server holds that port; over HTTP, any page or
process on the machine could have added any folder. The tldraw document stays keyed by the boards directory
(`canvasesNamespace`), all under the one origin, so each project keeps its own; the chat is one
for the app, above.

`sp start` sets no projects folder and serves its one project at `/`, as before.

## What the app remembers

`last.json` in the app's user data holds the agent chosen at startup, the project last opened
and the app's version then. A launch with an agent, a project that still exists and the same
major version goes to that project's home page, or the newest project's when the last is gone.
Last opened means opened through the app, from the startup page, New project or Open folder; a
tab or a card is a link the app does not hear about. Anything else is the startup page again: a first launch, or the first after a major
update, whose onboarding may ask something the last one did not. A patch or minor update does
not. A project given on the command line opens directly on its canvas, as before.
