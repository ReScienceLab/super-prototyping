# The window outlives the canvas

2026-09-22. With a tab per project, a click on another project's tab loaded that project's
address, and every page load mounted the agent's panel again: the message half-typed in it was
gone, the conversation was rebuilt from the server, and the panel flashed. A board the agent
wrote did the same through the canvas's live reload. The panel is the app's, one conversation
across every project (`2026-09-21-home-page.md`), so nothing that changes the project in front
should reach it.

## The window and the frame

The window is now its own page, `AppShell.tsx`, entered from `shell.tsx` at a project's address
and at its `home.html`. It holds the bar across the top, the agent's panel down the left, the home
page and the New project dialog, and loads no tldraw. Beside the panel is an iframe, and in it a
project's canvas, `canvas.html`, the entry that was `index.html` (`main.tsx`). The only thing a
tab switch, a card, New project, Open folder or a board write ever reloads is that frame.

A project is still its own pages at its own address, and that is why the frame is a frame rather
than a component. The canvas reads its project's index once, as it loads (`canvasIndex.ts`), and
its tldraw document is keyed by that project's boards directory; swapping projects inside one
document would mean tearing both down and building them again, which is a page load by another
name. Loading the frame is that page load, left where it costs nothing.

Rejected: keeping the draft in `sessionStorage` across the load. It keeps the text and not the
panel, so the flash, the scroll position, the caret and a run's stream reconnecting from event
zero would all stay. Rejected too: a web contents per tab in the desktop shell, which puts the
panel in one and the canvas in another, and would exist only in the app, not in a browser
against `sp start`.

## One address, two files

The window's address is what a person would copy or reload: `/p/<project>/?canvas=…#board`, or
`home.html`. The frame's is the same with `canvas.html` as the file (`frameUrl` and `windowUrl`
in `canvasUrl.ts`), and the window mirrors it with `history.replaceState` each time the canvas
says where it is. Because the panel's requests are relative, `__sp/agent` on the window's
address is the project in front's, so a message goes to the project on screen with no argument
naming it. The server keeps one list of runs for every project, so a run followed from one
project's address is still served after the address moves to another.

Each file sends a load in the wrong place to the right one: `canvas.html` loaded on its own
replaces itself with the window's address, and the window loaded inside the frame, by a link in
a board, replaces itself with the canvas.

## What crosses the frame

The two documents share an origin, so they talk through plain properties of each other's
`window`, one each way:

- `spShell.shown(tab, href)`, from the canvas, each time what it has in front changes: the bar's
  active tab, the window's address, and the tab added to the bar if it was not there.
- `spCanvas.goTo(tab)`, from the window, when a chip, a card or a row of the "+" is clicked. The
  canvas brings the tab forward and says so, or says it is another project's, and the window
  loads that project into the frame.

The canvas's hand-offs to the panel — a picture from a shape's +, "Make a new canvas for " from
the strip's + — are `CANVAS_ATTACH` events dispatched on `window.parent`, which is the window. A
`File` made in the frame's realm reads the same in the window's.

The desktop app's New project and Open folder answer the window with the project's address
instead of loading it (`desktop/main.ts`), so the window loads it into the frame. The startup
page, which is not the window, is still replaced by the project.

## Checked

`tsc -b`, `oxlint`, `vitest run` (23 files, 188 tests) and the desktop app's `bun test`. In the
built app over CDP: a draft typed into the panel, then six switches across two projects, an
example, home and back, with the panel the same DOM node and the draft intact after each. The
strip's + and a picture made in the frame's realm both reached the panel. A board touched on disk
reloaded the frame and left the window, the draft and the attached picture as they were. The
app's open answered `{ url }` without reloading the window. The static build, served by a plain
file server, opened a canvas in the frame with no panel, since no server is behind it.
